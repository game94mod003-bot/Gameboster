# Abolix — کلاینت VPN اندروید

**Abolix** یک کلاینت اندرویدی بر پایه‌ی هسته‌ی رسمی **sing-box libbox 1.14.4** است. ساختار Java/Gradle پروژه و الگوی بیلد بدون Gradle Wrapper از ZIP نمونه‌ی ارسالی حفظ شده‌اند.

## امکانات پیاده‌سازی‌شده

- اتصال VPN اندروید با `VpnService` و TUN واقعی مبتنی بر libbox.
- خواندن لینک‌های اشتراک و کانفیگ تکی: `VLESS`، `VMess`، `Trojan`، `Shadowsocks`، `Hysteria2` و `TUIC`.
- دریافت اشتراک فقط از HTTPS؛ ابتدا DNS عادی و در صورت شکست، تلاش مجدد با DNS-over-HTTPS کلادفلر و حفظ بررسی گواهی TLS و نام میزبان.
- ذخیره‌ی URL اشتراک، کانفیگ‌ها و اطلاعات سرورها با AES-GCM و Android Keystore.
- تست یک‌باره‌ی TCP برای سرور انتخابی و تست دستی TCP/443 برای YouTube، Telegram، Discord و Facebook.
- نمایش IP خروجی، کشور و ISP در زمان اتصال.
- نمودار سرعت دریافت/ارسال و شمارنده‌ی مصرف برنامه.
- تونل کامل دستگاه یا مسیریابی انتخابی برای Instagram، YouTube، Telegram، Discord و Facebook.
- به‌روزرسانی اشتراک هنگام ورود به برنامه، در صورت فعال بودن گزینه و ذخیره بودن URL.
- رابط فارسی چندبخشی، رنگ‌های قابل تغییر و حالت نمونه‌برداری سبک‌تر نمودار.
- GitHub Actions: ساخت APK امضاشده در صورت وجود Secrets امضا؛ در غیر این صورت ساخت APK دیباگ.

## ساخت APK با GitHub Actions

1. محتویات ZIP را در ریشه‌ی یک مخزن GitHub قرار بده و به شاخه‌ی `main` یا `master` push کن.
2. از بخش **Actions** گردش‌کار **Abolix Android Build** را اجرا کن.
3. اگر Secrets امضا تنظیم نشده باشد، فایل `abolix-debug-apk` را از بخش **Artifacts** همان اجرای Workflow دریافت کن.

### ساخت Release امضاشده

ابتدا یک Keystore خصوصی بساز (این فایل را امن نگه دار و در مخزن قرار نده):

```bash
keytool -genkeypair -v -keystore abolix-release.jks -keyalg RSA -keysize 4096 -validity 10000 -alias abolix
base64 -w 0 abolix-release.jks
```

خروجی Base64 و سه مقدار رمز/Alias را به‌عنوان چهار Secret زیر در تنظیمات مخزن GitHub ثبت کن:

- `ABOLIX_KEYSTORE_BASE64` — محتوای فایل Keystore به‌شکل Base64.
- `ABOLIX_STORE_PASSWORD` — رمز Keystore.
- `ABOLIX_KEY_ALIAS` — نام Alias.
- `ABOLIX_KEY_PASSWORD` — رمز کلید.

فایل Keystore و رمزها را هرگز داخل مخزن commit نکن. با وجود هر چهار Secret، Workflow نسخه‌ی Release امضاشده را می‌سازد. با push کردن تگ مانند `v1.0.0`، APK به GitHub Release همان تگ نیز پیوست می‌شود. برای آپدیت‌های آینده باید همان Keystore قبلی را نگه داری؛ امضای متفاوت، نصب را به‌عنوان برنامه‌ای جداگانه تلقی می‌کند.

## محدودیت‌های فنی مهم

- این نسخه **یک هسته‌ی sing-box** دارد. هسته‌ی جداگانه‌ی Xray در کنار آن ادغام یا بسته‌بندی نشده است؛ ادعای ادغام دو هسته در این سورس درست نیست. sing-box از خانواده‌پروتکل‌های ذکرشده پشتیبانی می‌کند.
- تستی که در رابط «پینگ» نامیده شده، زمان برقراری اتصال TCP است، نه ICMP ping. تست سرور از تونل VPN محافظت می‌شود تا وارد حلقه‌ی مسیریابی نشود؛ تست سایت‌ها در زمان اتصال از مسیر فعلی برنامه انجام می‌شود.
- شمارنده‌های ترافیک مربوط به UID خود Abolix و از زمان روشن‌شدن دستگاه هستند؛ این اعداد لزوماً مصرف تمام برنامه‌های گوشی را نشان نمی‌دهند.
- انتخاب برنامه در این نسخه به پنج اپ فهرست‌شده محدود است. در حالت بدون انتخاب، تونل کامل دستگاه فعال می‌شود؛ با انتخاب اپ‌ها فقط همان‌ها و خود Abolix وارد تونل می‌شوند.
- حالت کم‌مصرف، دفعات نمونه‌برداری نمودار را کاهش می‌دهد؛ فشرده‌سازی عمومی ترافیک رمزنگاری‌شده ممکن نیست و کاهش واقعی حجم مصرف به پروتکل و سرویس مقصد وابسته است.
- مسیر DNS-over-HTTPS فقط یک مسیر بازیابی برای حل نام دامنه است؛ اعتبارسنجی TLS خاموش نمی‌شود و محدودیت دسترسی سرور اشتراک دور زده نمی‌شود.
- برخی پارامترها یا افزونه‌های اختصاصی ارائه‌دهنده ممکن است در لینک‌های اشتراک وجود داشته باشند که این نسخه پشتیبانی نمی‌کند؛ موارد شناخته‌شده‌ی ناسازگار به‌جای تبدیل بی‌صدا رد می‌شوند.
- هیچ APK ناشناخته‌ای را نمی‌توان تضمین کرد که Play Protect هرگز درباره‌ی آن هشدار ندهد. امضای پایدار، مجوزهای حداقلی و انتشار شفاف ریسک هشدار را کمتر می‌کنند، اما تصمیم نهایی با سیستم امنیتی دستگاه است.
- در محیط ساخت فعلی Android SDK و Gradle نصب نبودند؛ بنابراین این بسته در اینجا بیلد کامل یا روی گوشی آزمایش نشده است. Workflow گیت‌هاب برای اجرای بیلد واقعی تنظیم شده و نتیجه‌ی آن باید پس از push بررسی شود.
